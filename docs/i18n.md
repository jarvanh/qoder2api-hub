# i18n design — Qoder gateway dashboard

Status: **design, not implemented.** Scope agreed: first English pack covers *chrome + shell*
only; the log panel stream is excluded; missing keys fall back to the original Chinese.

Repo prose is Chinese; this doc is English because it specifies the English integration.

---

## 1. Goal / non-goals

**Goal.** A locale system where adding a language is *dropping one JSON file into a folder*,
and any string not present in that file renders as the current Chinese source text — never
blank, never a raw key. A language button sits in the header, immediately left of the theme
selector.

**Non-goals for v1.**
- No `t('key')` refactor of the ~650 JS call sites.
- No translation of the `/logs` freeform stream.
- No full sweep of backend diagnostic prose (the mechanism covers it; the pack does not yet).
- No RTL, no plural/selectors, no per-locale number/date formatting.
- No build step, no npm dependency, no Python dependency.

**Why this rules out the standard refactor.** 75% of the CJK characters live in the JS block,
and **48% of the 626 JS string literals are fragments concatenated with runtime values**
(`'最近一次对话（' + at + '）走了 ' + nameOf(r)`). Separately, ~315 Chinese literals in the
Python backend arrive over `fetch` and are rendered into toasts and error boxes. A
`t('key')` rewrite would touch ~650 lines, need ~1,100 invented keys, still miss all backend
text, and break C8.

**Consequence.** Translate at the DOM boundary. The observer sees the *final rendered
string*, so static HTML, JS-generated content and backend messages are all covered by one
mechanism, additively.

## 3. Architecture

```
i18n/en.json  ─┐
i18n/xx.json  ─┤─► L1 discovery   GET /i18n/manifest, GET /i18n/<code>.json
               │                  (folder scan at request time → new file = new language)
               ▼
        L2 core        QD_I18N.t(text)  — pure, DOM-free, memoised
                       tier1 messages → tier2 patterns → tier3 fragments → tier4 return input
               ▼
        L3 apply       TreeWalker + MutationObserver
                       text nodes + title/placeholder/aria-label
                       excludes .log-line, <code>, <pre>
               ▼
        L4 shell       pre-paint IIFE + qd-lang + localStorage pack cache + language button
```

L2 is deliberately free of `document`/`window` so it can be sliced and unit-tested in node
without a DOM (C6). L3 is the only layer that touches the DOM.

---

## 4. File layout

```
i18n/
  README.md      # the pack contract, for translators
  en.json        # first integration
  <code>.json    # drop a file → language appears. No code change.
```

No `i18n/locales.json` index, no registration step — the manifest is generated by scanning
the folder.

## 5. Locale pack schema

```json
{
  "@locale": { "code": "en", "name": "English",
               "dir": "ltr", "order": 10, "version": 1 },

  "messages": {
    "数据指标看板": "Analytics",
    "运行日志": "Logs"
  },

  "patterns": {
    "最近一次对话（{0}）走了 {1}：被自动换区":
      "Last conversation ({0}) used {1}: auto-switched"
  },

  "fragments": {
    " 个 Key 生效": " keys active",
    "（共": " (total "
  }
}
```

- **Keys are the Chinese source text**, verbatim, trimmed for comparison. This *is* the
  fallback mechanism: an untranslated string has no key, so L2 returns its input.
  "Trimmed" is one of four passes, in this order: exact → trimmed → whitespace-collapsed
  (`\s+`→single space, because a text node keeps the HTML's newlines and indentation) →
  pattern scan. The exact pass must come first, or every whitespace-significant
  `fragments` key loses.
- `patterns` use `{0}`/`{1}` slots, matched left-to-right against capture groups. Slot order
  may differ between source and target, which is what buys correct English word order.
- **Slot values are looked up too**, to a depth of 2 (`MAX_SLOT_DEPTH`). Without this,
  `颜色主题: 跟随系统 (当前浅色)` renders as `Color theme: 跟随系统 (当前浅色)` — half a
  sentence in each language. The cap exists because a pattern whose source is only slots
  (`{0}`) compiles to `^(.+)$`, eats the whole string, and would otherwise recurse forever;
  the pack suite rejects that shape instead of leaning on the cap.
- `@locale.version` is the cache's only invalidation signal: the pack lives in
  `localStorage`, and the boot compares this number against `/i18n/manifest`. Editing a pack
  without raising it is invisible to everyone who has visited before (see §8).
- Patterns are tried in the order they appear in the file, first match wins. Put the more
  specific source first.
- `@locale.name` is what the dropdown lists; `order` sorts it; `dir` is reserved for RTL.
- Unknown top-level keys are ignored, so a pack can grow without breaking an older core.
- A malformed pack must degrade to "no translations", never break the page (see §12).

## 6. Backend changes — `qoder_proxy.py`

**6a. Module constant**, next to `DASHBOARD_HTML` at `qoder_proxy.py:413-414`:

```python
I18N_DIR = os.path.join(os.path.dirname(os.path.abspath(__file__)), "i18n")
I18N_FILE_RE = re.compile(r"^[a-zA-Z0-9][a-zA-Z0-9._-]{1,31}\.json$")
```

**6b. Two GET routes**, inserted immediately before the dashboard dispatch at
`qoder_proxy.py:8969` (`if path in ("/", "/dashboard", "/ui"):`):

```python
if path == "/i18n/manifest":
    return self._i18n_manifest()
if path.startswith("/i18n/"):
    return self._i18n_pack(path[len("/i18n/"):])
```

**6c. Handlers**, beside `_dashboard()` at `qoder_proxy.py:9556`:

```python
def _i18n_manifest(self):
    packs = []
    try:
        names = sorted(os.listdir(I18N_DIR))
    except Exception:
        names = []
    for name in names:
        if not I18N_FILE_RE.match(name):
            continue
        meta = self._i18n_meta(os.path.join(I18N_DIR, name))
        if meta:
            packs.append(meta)
    packs.sort(key=lambda p: (p.get("order", 100), p.get("code", "")))
    return self._json(200, {"default": "zh", "packs": packs})
```

`_i18n_pack(code)` validates `code` against `I18N_FILE_RE` **before** touching the
filesystem, then reads and echoes the bytes.

**Security — this is the one place a mistake is not cosmetic.** The path is attacker-
controlled and the route is unauthenticated (C4). Requirements:
- Reject anything not matching `I18N_FILE_RE`. No `..`, no `/`, no `\`, no NUL, no absolute
  path. The regex is an allowlist anchored at both ends and requires a `.json` suffix.
- Do **not** build the path with string concatenation of user input; match the name, then
  `os.path.join(I18N_DIR, matched_name)`.
- After opening, verify `os.path.realpath` still starts with `realpath(I18N_DIR)` — defends
  against a symlink planted in `i18n/` escaping to e.g. `accounts/`.
- Serve only `.json`; never fall back to "serve whatever the folder holds".
- On any failure return 404, not a stack trace — `_error()` bodies reach a browser toast.

**Consequence to accept explicitly:** translation files become public on the same port as
the panel. They contain UI copy only. Do not put anything sensitive in `i18n/`.

**Other backend notes.** Read per request (matches C3, so a dropped file works without a
restart). `Cache-Control: no-store` for consistency with `_dashboard()`. No change to
`_is_panel_route`. No change to `quiet_prefixes` at `:8577-8581` — `/i18n/*` is fetched once
per page load, not polled. Python 3.9 floor (C7): `%`-formatting, no `match`, no `X | Y`
annotations, no `str.removeprefix` reliance beyond 3.9.

## 7. Frontend changes — `dashboard.html`

**Block-order rule (hard, from C5/C6).** The file currently has exactly two script blocks:
`[0]` = head/theme IIFE (`857-974`), `[1]` = main script (`1790-6306`). `_test_dashboard_full_load.js`
evals `blocks[length-1]` and asserts `blocks[0]` is the theme script.

Therefore:
- The **L4 pre-paint bootstrap** is appended *inside* the existing head block → `blocks[0]`
  stays the head block and its `qd-theme` / `__MAIN_TAB__` / `prefers-color-scheme` regexes
  still match.
- The **L2 core + L3 engine** go in a **new third block placed between the head block and the
  main script** (i.e. just before `<body>` at `:976` or just after `</header>` at `:1041`).
  `blocks[0]` and `blocks[length-1]` are both preserved.
- Never append a block after the main script — that would silently change what the full-load
  suite evaluates and the stub test would start passing the wrong code.
- The new block must not contain any literal used as a `dash_extract` anchor (C6).

**7a. L2 core** — pure, no DOM:

```js
window.QD_I18N = (function(){
  var MSG = {}, PAT = {}, FRG = {}, MEM = new Map(), READY = false;

  function compile(tpl){
    var slots = [];
    var re = tpl.replace(/[.*+?^$()|[\]\\]/g, '\\$&')     // { } survive on purpose
                .replace(/\{(\d+)\}/g, function(_, i){ slots.push(+i); return '([\\s\\S]+?)'; });
    return { re: new RegExp('^' + re + '$'), slots: slots };
  }

  function fill(tpl, args){
    return tpl.replace(/\{(\d+)\}/g, function(_, i){
      var v = args[+i]; return v === undefined ? '' : v; });
  }

  function lookup(src){
    var t = src.trim();
    if (!t) return src;
    // Evaluation order is cheapest-and-most-reliable first, so it is deliberately
    // messages -> fragments -> patterns. A fragment is still an exact dictionary
    // hit; a pattern is an O(n) regex scan that could mis-capture.
    if (MSG.hasOwnProperty(t)) return MSG[t];                 // tier 1 exact
    if (FRG.hasOwnProperty(t)) return FRG[t];                 // tier 3 fragments (exact)
    if (/\d/.test(t) || t.length > 14) {                      // tier 2 patterns, gated
      for (var k in PAT) {
        var c = PAT[k].call || (PAT[k].call = compile(k));
        var m = c.re.exec(t);
        if (m) { var a = {}; c.slots.forEach(function(s, i){ a[s] = m[i+1]; });
                 return fill(PAT[k], a); }
      }
    }
    return src;                                               // tier 4 fallback = the requirement
  }

  function t(src){
    if (typeof src !== 'string' || !READY) return src;
    if (MEM.has(src)) return MEM.get(src);
    var out = lookup(src);
    MEM.set(src, out);
    return out;
  }
  return { t: t, load: load, isReady: function(){ return READY; } };
})();
```

`typeof src !== 'string'` guard matters: `t()` is called on node values, but a future
`textContent = t(0)` must not throw.

**7b. L3 apply engine** — the only DOM-touching piece:

```js
var SKIP_ATTRS = ['title', 'placeholder', 'aria-label'];
var SKIP_SEL   = ['.log-line', 'code', 'pre'];   // agreed exclusions
var seen = new WeakSet();

function inSkip(node){
  var el = node.parentElement;
  return !!(el && el.closest && SKIP_SEL.some(function(s){ return el.closest(s); }));
}

function walk(root){
  if (!document.createTreeWalker) return;                     // stub safety
  var w = document.createTreeWalker(root, 1 /* SHOW_ELEMENT */, null);
  var el;
  while ((el = w.nextNode())) {
    if (inSkip(el)) continue;
    for (var i = 0; i < el.childNodes.length; i++) {
      var n = el.childNodes[i];
      if (n.nodeType === 3) applyText(n);
    }
    applyAttrs(el);
  }
}

function applyText(n){
  if (seen.has(n)) return;
  var out = QD_I18N.t(n.nodeValue);
  seen.add(n);
  if (out !== n.nodeValue) n.nodeValue = out;                 // see re-entrancy proof
}
```

**Re-entrancy proof.** Writing `nodeValue` re-fires the observer. It terminates because the
tier-4 fallback is *identity for untranslated input*: the second visit passes English text
that is not a dictionary key, so `t()` returns it unchanged, so `out !== n.nodeValue` is
false, so nothing is written. The `seen` WeakSet makes that a cheap early-out rather than a
second dictionary pass. The one way this loops is a pack whose `messages` key is itself an
English string that maps elsewhere — worth a load-time validation warning (§12).

**Perf guards** (the dashboard polls every 5s and re-renders tables):
- `MEM` Map: each distinct source string is resolved once per session, not once per node.
- Tier 2 is gated behind a digit-or-length test so the ~400 plain labels never scan the
  pattern list; pattern matching stays O(patterns) only for concatenated sentences.
- Batch observer callbacks in a `requestAnimationFrame`, dedupe the record list — **and always
  arm a `setTimeout` fallback for the same flush**. `rAF` does not fire at all while the tab is
  hidden or occluded (measured: `visibilityState=hidden`, zero frames), and switching language
  goes through a reload, so an rAF-only scheduler silently leaves the whole page untranslated
  for anyone who backgrounds the tab. The flush drains `pending` and nulls it, so whichever
  callback arrives first does the work and the other returns — no extra state, no double walk.
- Never hang per-pattern compiled regexes off `PAT[k]`. `PAT[k]` *is* the target string, and
  the block is `'use strict'`, so `PAT[k].call = …` throws `TypeError` and kills the walk
  partway through the document (attributes done, body text left in Chinese). Keep the cache in
  its own `Map`, cleared by `load()`. The suite evals the extracted core under `'use strict'`
  for exactly this reason: a sloppy `new Function` swallows the same mistake silently.
- `seen` WeakSet prevents re-walking untouched subtrees.
- `.log-line` excluded — removes the highest-volume mutation source from the cost model.

**7c. L4 shell.** Append to the head block, mirroring the theme IIFE's shape and reasoning:

```js
var LANG_KEY = 'qd-lang', PACK_CACHE = 'qd-i18n-pack';
// getPref(): stored choice → navigator.language match → 'zh' (source, no pack)
// At DOMContentLoaded: if a pack is cached in localStorage, hydrate L2 synchronously
// and walk() once; then fetch /i18n/manifest and start the observer.
```

`<html lang="zh-CN">` at `dashboard.html:2` must be updated to the active locale code on
switch — it is what screen readers and browser spellcheck use, and leaving it stale is a
real accessibility bug, not a cosmetic one.

**7d. Language button.** Insert in `.header-right` at `dashboard.html:1007`, as the **first
child, before `<div class="theme-dropdown-wrap" id="themeDropdownWrap">` at `:1008`**:

```html
<div class="theme-dropdown-wrap" id="langDropdownWrap">
  <button type="button" class="theme-btn" id="langToggleBtn"
          onclick="toggleLangMenu(event)" title="界面语言" aria-label="切换界面语言"
          aria-haspopup="true" aria-expanded="false">
    <span id="langToggleIcon" class="theme-btn-icon">…globe svg…</span>
  </button>
  <div class="theme-dropdown" id="langDropdown" role="menu" aria-label="选择界面语言"></div>
</div>
```

Options are rendered at runtime from `/i18n/manifest` — that is what makes the folder
plug-and-play; the markup carries no language list. Reuse `.theme-btn`, `.theme-dropdown`,
`.theme-option`, `.theme-opt-text`, `.theme-opt-check` verbatim so the button inherits the
dark-theme overrides at `:264-286` and the `themePop` animation for free. **Zero new CSS is
required**, which also means zero new `[data-theme="dark"]` rules to forget.

Mirror the theme's outside-click and `Escape` close handlers (`:931-951`), extended to cover
both wraps so opening one closes the other.

## 8. Boot sequence and the flash

| Visit | What happens |
|---|---|
| 1st, no choice stored | Chinese paints → DCL → manifest + `en.json` fetched → walk → English. One visible switch. |
| 2nd+ | Pack hydrated from `qd-i18n-pack` at parse time, walk at DCL, before the first poll returns. No visible switch, and no pack fetch at all when the cached `version` matches the manifest. |
| After | Observer only. |

The hydrate lookup uses `qd-lang` **or** the browser's primary language subtag, whichever
exists. Auto-detected users never have `qd-lang` written, so hydrating from `getPref()` alone
put every one of them back on the first-visit path (visible Chinese + a 13 KB refetch) on
every single load. Same guess, same cache key.

**Cache invalidation.** `@locale.version` is compared against `/i18n/manifest` on every boot.
Mismatch → refetch, rewrite the cache, and reload once (`location.replace`) — because the page
was already painted with the old pack and text nodes that entered `seen` are never re-translated,
so an in-place swap would leave old and new renderings mixed. After the reload the versions match,
so it cannot loop. A pack that disappears from `i18n/` entirely is handled the same way: the
cache is dropped and the page reloads into the source language rather than staying in a language
the server no longer offers.

The theme system solved the identical problem by inlining a pre-`<body>` script
(`dashboard.html:858-860` says so explicitly). i18n cannot fully — the dictionary is
async-fetched data, not a boolean. localStorage caching gets visit 2+ to parity, which is
the practical ceiling without a build step or a server-side cookie render.

**Rejected alternative.** A `qd-lang` cookie would let `_dashboard()` inline the chosen pack
server-side and eliminate the first-visit flash entirely. Rejected for v1: it adds a
backend/frontend coupling, makes the HTML response locale-dependent (worse for caching and
for the C3 read-per-request path), and buys one frame on a once-per-browser lifetime.
Revisit only if the flash proves unacceptable.

localStorage budget: an English chrome pack is ~25–40 KB of JSON; the 5 MB quota is not a
concern. Guard with `try/catch` exactly as `getPref()` does for the theme.

| Theme dropdown labels | 3 |

Keys were extracted programmatically from `dashboard.html` rather than retyped, then asserted
against the file by `tests/_test_i18n_packs.py` — retyping is how a key silently stops matching.

The `patterns` count grew past the estimate in a second pass driven by the live DOM: the
first pass only covered strings sitting in static markup, while most of the shell is composed
at runtime (`'累计消耗 ' + fmt(x) + ' Token'`, `'签到 ' + times + ' · 保活 ' + …`). A browser
dump of every text node whose `t()` returned its input is the only way to find that set;
`docs/i18n.md` §10 requires it. Patterns that begin with a slot (`{0} 天`) must be listed
**after** every longer pattern that could also match them (`临期优先窗口 {0} 天`, `近 {0} 天`),
because patterns win in file order — `{0} 天` alone turned the backend-supplied range label
`近 7 天` into `近 7 days`.

Deliberately **out of v1**: the ~242 short concat fragments, the ~145 log-panel prose
strings from `qoder_tasks.py` / `qoder_scheduler.py`, and the ~315 backend literals. They
fall back to Chinese, which is the designed behaviour, and they can be added to `en.json`
incrementally with no code change.

After the second pass, the live page had **zero** untranslated strings left that come from
`dashboard.html`. Everything still Chinese is data the panel only displays, not chrome it
owns, and none of it is keyable in `en.json` because the reachability assertion can only see
`dashboard.html`:

| Still Chinese | Source |
|---|---|
| Model names' one-line descriptions and `title` tooltips in the catalog table | `/v1/models` upstream payload |
| Agent Setup blurbs (`Charm Crush；providers 注册…`) | `qoder_agents.py:668` |
| VM evidence lines (`处理器型号：…`, `官方风控判定：…`, `· Hyper-V（微软）`, `风险档位 高`) | `/health` fingerprint fields |
| Scheduler status mode text after `Running ·` (`排程：每日签到 …`) | `mode_cn` / `mode_intl` from the scheduler |
| The log stream | excluded by design (§1) |

Adding them means either keying backend strings (a pack that must ship with the backend, not
dropped into `i18n/`) or translating them server-side — both out of scope for the plug-and-play
contract, which promises that `i18n/*.json` alone is enough.

## 10. Verification plan

New suites, following the `_test_*` convention (`tests/run_all.py` auto-discovers both `.py`
and `.js`):

- `tests/_test_i18n_core.js` — node, no DOM. Slice the L2 block out of `dashboard.html`,
  `new Function` it **under `'use strict'`** (the real block is strict; a sloppy eval hides
  exactly the class of bug that broke the browser run), then assert: tier-1 hit; tier-2 pattern
  with reordered slots, including slot values translated through; tier-3 fragment, including
  that a leading space is part of the key; the whitespace-collapse pass, and that it stays
  *behind* the exact lookups; **tier-4 returns the input byte-identical for an unknown key**;
  `t(non-string)` does not throw; `t(t(x)) === t(x)` (observer termination); whole-pack
  rejection on a malformed tier without breaking the others; and the `schedule()` flush with a
  rAF that never fires.
- `tests/_test_i18n_route.py` — real server on an ephemeral port. Assert: manifest lists a
  dropped file **without a restart** (this is the plug-and-play contract); `..%2f`, `%00`,
  absolute paths, `.py` and non-`.json` names all 404; `realpath` symlink escape is refused;
  the route answers **without a panel password** while `/accounts` still demands one;
  missing `i18n/` folder yields `{"packs": []}`, not a 500.
- `tests/_test_i18n_packs.py` — every `i18n/*.json` parses, has `@locale.code` matching its
  filename and an integer `@locale.version` (the cache's only invalidation signal), maps no key
  to itself, contains no `{n}` slot in a target that is absent from its source pattern, and
  has no catch-all pattern source (`{0}` alone). The load-bearing one: **every `messages` key
  must be reachable from `dashboard.html`** — literally, or after the whitespace-collapse pass.
  A mistranscribed key fails silently in the UI (it just looks "not translated yet"), and this
  check caught five such keys on its first run. It also rejects a value that is itself another
  key, which would break the `t(t(x)) === t(x)` identity the observer's termination rests on.
- Extend `tests/_test_dashboard_full_load.js` with: `blocks[0]` is still the theme script,
  `blocks[length-1]` is still the main script, and the i18n block sits between them. This
  pins C5/C6 so a future reordering fails loudly instead of quietly testing the wrong code.

Regression gate: `python tests/run_all.py` then `python scripts/check_clean_checkout.py`
(the new `i18n/` files must be committed, not left as untracked strays).

**Browser pass (required — none of the three suites can see it).** These are the failures that
only appeared against a real `dashboard.html` in a real engine, so the pass is part of the gate,
not a formality:

- `PAT[k].call` threw `TypeError` under `'use strict'` and aborted the walk mid-document: the
  header attributes were English, everything below was Chinese, and nothing was logged.
  Now asserted by eval'ing the extracted core under `'use strict'`.
- rAF-only batching never flushes in a hidden tab. Now asserted with an injected rAF that

- Slot values stayed in the source language (`Color theme: 跟随系统 (当前浅色)`), so
  mixed-language sentences shipped. Now recursed to depth 2.
- `walk()`'s `TreeWalker(SHOW_ELEMENT)` never yields the root it was given, so every leaf

- `@locale.version` stayed at 1 while `en.json` gained 100 keys, so repeat visitors were served

## 11. Risks

| Risk | Severity | Mitigation |
|---|---|---|
| Sentences split across sibling text nodes translate word-salad. | Medium | Concatenation lands in one `textContent`, so most are single nodes. The 43 `innerHTML` sites with inline tags are the exposure; handle via `patterns`, and accept fallback otherwise. |
| Observer cost on 5s polling re-renders. | Medium | Memo Map + tier-2 gating + `.log-line` exclusion + per-frame batching. Batching itself was the hazard, not the mitigation: rAF-only leaves a hidden tab permanently untranslated (§7). |
| A DOM-boundary bug is invisible to every suite (strict-mode throw, missing frame, mixed-language slot). | **High** | The browser pass in §10 is part of the gate. All three defects above passed `node --check`, 41 core assertions and 83 suites before being found in the page. |
| First-visit flash. | Low, visible | localStorage pack cache; documented above. |
| A block reorder breaks two node suites silently. | High if it happens | Explicit assertion added to the full-load suite (§10). |
| Path traversal on the public route. | **High** | Allowlist regex + `realpath` containment + 404-not-stacktrace (§6). This is the one item that must not be simplified. |
| Half-translated long diagnostics read badly. | Low | Accepted for v1 scope; add to `en.json` later. |
| Someone translates a string that a test greps for in source (C8). | Low | The DOM engine never edits source literals, so C8 stays green by construction. |
