# v1.8.0 网关性能优化与验证

## 范围

对比参考提交 `70ba58b`（v1.7.30）与本次实现，使用本地合成数据，不调用付费上游，不读取真实账号/用量。优化的是网关本身的 CPU、内存分配、日志 I/O 与重复轮询；不把上游排队或模型生成速度归为性能收益。

## 可复现基准

```bash
python scripts/benchmark_gateway.py --reference 70ba58b --rows 15000
```

参考版本的指定函数由 git 取出并用 AST 隔离，不启动旧服务器。长历史为 40 条、每条约 20,000 字符；流式为 1,000 个普通文本帧；日志为 15,000 条合成流水。每项多次运行取中位数。

本机 Windows 11、项目内置 Python 3.12.14 一次实测：

| 项目 | 优化前 | 优化后 | 说明 |
|---|---:|---:|---|
| 约 24 万字符无匹配文本清洗 | 3.3931 ms | 0.4659 ms | 常见无命中路径用快速子串判定，保持脱敏语义 |
| 40 条长历史构造 | 22.1102 ms | 3.0772 ms | 清洗快路径 + 模板深拷贝去 JSON 往返 |
| DSML 阶段处理 1,000 帧 | 23.5495 ms | 15.3218 ms | 仅复制修改路径，不再 JSON 深拷贝整个帧 |
| tool-tag 阶段处理 1,000 帧 | 29.9688 ms | 19.7675 ms | 同上；所有工具恢复守卫保留 |
| stats 重复查询（日志不变，缓存命中） | 353.5258 ms | 0.3339 ms | 未命中仍正常扫描 |
| analytics 重复查询（日志不变，缓存命中） | 325.8481 ms | 0.1749 ms | 不等同于持续写入场景收益 |

这些是同一进程的离线微基准，受硬件和并发负载影响，不代表所有请求或端到端首字速度提高相同倍数。

## 请求与流式路径

- 用便宜的 ASCII 子串扫描过滤大多数无指纹文本，只有有候选才跑大小写不敏感正则；原脱敏匹配与替换规则不变。
- 模板改为 `copy.deepcopy`，不浅拷贝、不共享可变模型/参数/会话结构。
- 首次出站体积预检只计算 `4 * ((len(utf8_plain)+2)//3)`，避免为了大小检查完整编码一次。真实账号和 session 落定后才编码签名；再检查最终真实长度，保持 413 边界。
- DSML/tool-tag 普通内容帧只复制 `choices[0].delta` 的修改路径，其他 choice、usage、未知扩展字段照常保留。没有跳过工具回读、代码围栏守卫或失败终态。
- 没有改动签名算法、跨账号复用 COSY 身份或默认裁剪真实历史。

## 看板与用量统计

- `/usage/stats`、`/usage/analytics` 结果缓存固定 TTL=10s（大于 5s 轮询周期）。8 个相同冷查询只执行一次计算；不同 key 不持有全局扫描锁。
- 最近请求页的全量行数统计缓存固定 TTL=5s，保留原本的行数/区域语义，尾部请求行仍即时读取。
- 缓存 key 包含日志绝对路径、设备/inode、大小和纳秒级修改/变化时间；追加、截断、替换立即失效。跨日期、时区、账号昵称/区域/积分变化也单独分键。
- 缓存最多 32 项、16 MiB 聚合 JSON；不缓存推理正文或凭据。命中时返回独立结果，调用者修改不污染共享快照。
- 日用量缓存修复“命中刷新 TTL”问题：只更新 LRU 访问次序，不修改原始到期时间。持续轮询也会重新计算。
- `/health.analytics_cache` 可查看 entries/bytes/hits/misses/coalesced/inflight。

日志持续写入时指纹会变，正确性优先，仍需重新聚合；没有承诺所有场景都零扫描。
