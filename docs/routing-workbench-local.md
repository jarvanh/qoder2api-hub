# 路由编排工作台（本地待确认）

## 界面与交互

依据截图以及CPAMC源码的 TierLadder.tsx、PolicyPanel.tsx、logic.ts、MemberCard 和 RoutingSaveBar 适配。本项目仍调度Qoder国内/国际账号，不复用参考项目的供应商API。

- 左侧优先层轨道，账号显示昵称、区域、分组、可用状态及静态分配占比。
- 原生拖拽：移到另一层、放进层间空隙建立新层；空来源层自动清除。
- 卡片菜单提供权重编辑、移到上一/下一层、单独放末层、移出编排，支持不使用拖拽的操作方式。
- 层可改名、整层上下移动、删除；添加账号弹窗支持搜索与按组选中。
- 顶部模型自动完成与Key选择器，预览当前未保存草稿，不必先保存再试。
- 保存栏统一提交层级、权重、网关策略与旧精细规则；放弃恢复整套草稿。旧精细规则继续保留，与层成员及Key范围取交集。
- 服务器revision防止其他窗口的旧草稿覆盖新配置。

## 实际调度

从上到下选择第一个有可用账号的层；同层轮询、平滑加权轮询或优先填满。权重默认1、0表示在加权策略下暂停分配；可用同层权重3:1经40次离线选号为30:10。

会话亲和开启：允许范围内、未冷却的已绑定账号优先；不可用时转移。关闭：不读取或新建账号亲和绑定，仍保留上游会话身份防止对话混淆。

重试轮数0–3：首轮候选全部尝试失败后允许的额外轮数。每轮最多账号0–256：0表示本轮可尝试所有授权候选。不会绕过账号冷却，不重复发送已有输出；图片转换超时与确定性请求错误仍遵守原来的专门快速失败逻辑。原同账号瞬时错误处理和队列预算仍保留。

Key限制、区域、模型护栏、团队租约继续生效。编排明确保存为空时拒绝请求，不会把空配置解释成全账号；旧版仅rules配置未被动启用新策略。新账号默认不自动进入已明确保存的层，需添加以免意外扩权。

## 存储与接口

accounts/admin/routing.json增加tiers、policy、board_enabled与revision，原rules保留。GET /admin/routing读取完整方案；POST /admin/routing/save原子保存；POST /admin/routing/preview支持draft预览。全部要求面板会话。

浏览器验证使用临时假账号，不修改正式账号编排。测试产物位于 logs/tests/routing-browser-result.json、routing-desktop.png、routing-mobile.png。

本轮不commit、不push、不tag、不Release、不发布镜像，版本仍1.8.0。
